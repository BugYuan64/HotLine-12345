## 一、文档概述

### 1.1 文档目的

本文档定义 12345 政务热线工单智能分类与诉求预判系统的全部 API 接口规范，包括：

- 接口路径、请求方式、请求参数、返回响应
- 接口功能描述与技术选型说明
- 业务逻辑流程与实现要点

### 1.2 系统架构

```
┌─────────────────────────────────────────────────────────────┐
│       客户端（市民小程序 + Web管理端 + 部门端工作台）          │
├─────────────────────────────────────────────────────────────┤
│        Nginx 网关（HTTPS + JWT + 限流 + 敏感数据脱敏）        │
├────────────────────────┬────────────────────────────────────┤
│  Java 业务服务          │  Python AI / RAG 服务               │
│  Spring Boot           │  FastAPI                           │
│  /api/v1/public/ 市民端 │  /ai/v1/ 内部调用（IP白名单+签名）    │
│  /api/v1/admin/ 管理端  │  · 关键词规则 + 大模型语义 + RAG检索  │
│  /api/v1/staff/ 部门端  │  · jieba分词 + 向量检索             │
├────────────────────────┴────────────────────────────────────┤
│     MySQL 8.0 + Redis + Milvus(生产)/Chroma(开发) 向量库      │
└─────────────────────────────────────────────────────────────┘
```

### 1.3 技术选型依据

| 层级 | 技术 | 选型理由 |
|------|------|---------|
| 网关 | Nginx | 高性能反向代理，内置限流，支持 HTTPS 终结与敏感字段脱敏 |
| 业务后端 | Java + Spring Boot + MyBatis | 企业级稳定性，政务系统主流生态，RBAC 权限模型成熟 |
| AI 后端 | Python + FastAPI | AI/ML 生态完整，jieba 分词、向量检索、大模型调用便捷 |
| 分类策略 | 关键词规则 + 大模型语义 + RAG 知识库检索 | 混合策略兼顾覆盖率和准确率，可降级兜底 |
| 向量库 | Milvus（生产）/ Chroma（开发演示） | 历史工单样本向量化检索，支撑 RAG 分类与问答 |
| 认证 | JWT | 多用户类型差异化认证（市民短信验证码 / 部门工号密码 / 管理员工号密码） |
| 密码存储 | bcrypt 加盐哈希 | 杜绝明文与可逆加密，满足等保要求 |
| 数据库 | MySQL 8.0 | 关系型业务数据，utf8mb4 字符集 |
| 缓存 | Redis | 验证码、登录失败锁、Token 黑名单、热点缓存 |
| 前端 | Vue3 + Element Plus | 市民端、管理端、部门端三端一致交互 |
| API 文档 | Knife4j / Swagger | 增强交互式文档，离线导出 |

### 1.5 API 版本规范

#### 版本规范定义

| 项目 | 说明 |
|------|------|
| 当前版本 | v1 |
| 路径格式 | `/{api_prefix}/v1/{module}/{resource}` |
| 版本升级策略 | 仅当出现破坏性变更（字段删除/类型变更/语义改变）时升级主版本号；新增字段/新增接口保持当前版本 |
| 多版本共存 | 服务端同时支持当前版本与上一版本，旧版本保留至少 6 个月后废弃 |
| 废弃通知 | 版本废弃前 3 个月，响应头增加 `X-API-Deprecated: true` 及 `X-API-Sunset: 2027-02-21` |

> **AI 服务路径特殊说明**：AI 服务独立部署，版本前缀为 `/ai/v1/` 而非 `/api/v1/ai/`，保持 AI 服务与业务服务的版本解耦。

#### 全量接口路径变更对照表（部分示例）

> 本次统一为所有既有接口路径追加 `/v1` 前缀，变更规则：`/api/{module}` → `/api/v1/{module}`；`/ai/{module}` → `/ai/v1/{module}`。其余接口遵循同一规则。

| 原路径 | 新路径 | 模块 |
|--------|--------|------|
| POST /api/public/auth/login | POST /api/v1/public/auth/login | 用户认证 |
| GET /api/admin/users | GET /api/v1/admin/users | 账号管理 |
| POST /api/staff/orders/{id}/receive | POST /api/v1/staff/orders/{id}/receive | 街道办工单接收 |
| POST /api/staff/orders/{id}/dispose | POST /api/v1/staff/orders/{id}/dispose | 街道办提交处置结果 |
| POST /api/staff/orders/{id}/audit-approve | POST /api/v1/staff/orders/{id}/audit-approve | 部门处置审核 |
| POST /api/admin/orders/{id}/final-approve | POST /api/v1/admin/orders/{id}/final-approve | Admin 终审与归档 |
| GET /api/public/appeal/{appealNo}/result | GET /api/v1/public/appeal/{appealNo}/result | 市民处置结果查看 |
| POST /ai/classify | POST /ai/v1/classify | 工单智能分类 |
| POST /api/common/upload | POST /api/v1/common/upload | 通用文件上传 |

#### 统一响应结构

```json
{
  "code": 200,
  "message": "success",
  "data": {},
  "timestamp": 1755772200
}
```

| 字段 | 说明 |
|------|------|
| code | 业务状态码，200=成功，非200=失败 |
| message | 人类可读提示信息 |
| data | 业务数据，失败时为 null |
| timestamp | Unix 时间戳（秒） |

> 完整成功/分页/错误响应示例见「2.3 统一响应格式」。

#### AI 降级特殊响应

> 当 AI 服务不可用时，业务接口不返回 500，而是返回 200 并在 data 中标记降级：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "classify_result": null,
    "ai_degraded": true,
    "fallback_message": "AI分类服务暂时不可用，请人工确认分类"
  },
  "timestamp": 1755772200
}
```

## 二、通用规范

### 2.1 通信协议

| 项目 | 规范 |
|------|------|
| 协议 | HTTP（生产环境全站 HTTPS） |
| 数据格式 | JSON |
| 字符编码 | UTF-8 |
| Content-Type | `application/json; charset=utf-8` |

### 2.2 认证方式

```
Header: Authorization: Bearer {JWT_Token}
```

- **市民端（/api/v1/public/）**: 手机号 + 短信验证码登录，返回短期 JWT Token（默认 2 小时有效）
- **部门端（/api/v1/staff/）**: 工号 + 密码登录，JWT 中携带用户 ID、角色、归属类型与辖区/部门
- **管理端（/api/v1/admin/）**: 工号 + 密码登录，JWT 中携带管理员角色与 RBAC 权限
- **Token 注销**: 退出登录将 Token 加入 Redis 黑名单，过期时间对齐 Token 剩余有效期
- **账号锁定**: 连续 5 次密码错误锁定 10 分钟，锁定期间禁止登录

### 2.3 统一响应格式

#### 成功响应

```json
{
  "code": 200,
  "message": "success",
  "data": {},
  "timestamp": 1785100800
}
```

#### 分页响应

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "list": [],
    "total": 100,
    "page": 1,
    "page_size": 20,
    "total_pages": 5
  },
  "timestamp": 1785100800
}
```

#### 错误响应

```json
{
  "code": 40001,
  "message": "参数校验失败：手机号格式不正确",
  "data": null,
  "timestamp": 1785100800
}
```

### 2.4 通用错误码

| 错误码 | 说明 | HTTP状态码 |
|--------|------|-----------|
| 200 | 成功 | 200 |
| 40001 | 参数校验失败 | 400 |
| 40002 | 验证码错误或已过期 | 400 |
| 40003 | 数据不存在 | 404 |
| 40004 | 数据已存在（工号/手机号冲突等） | 409 |
| 40101 | 未登录 / Token 已过期 | 401 |
| 40102 | Token 无效 / 已被注销 | 401 |
| 40103 | 账号已被停用 | 403 |
| 40104 | 账号未通过审核 | 403 |
| 40105 | 登录失败次数超限，账号已锁定 | 423 |
| 40201 | 权限不足 | 403 |
| 40202 | 管理员权限不足 | 403 |
| 40203 | 越权访问他人辖区/部门数据 | 403 |
| 50001 | 服务器内部错误 | 500 |
| 50002 | AI 服务调用失败（已降级） | 500 |
| 50003 | 第三方服务调用失败（短信/OCR 等） | 500 |

### 2.5 安全规范

| 维度 | 方案 | 实现位置 |
|------|------|---------|
| 传输安全 | 全站 HTTPS + 接口签名 + 防重放(nonce+timestamp) | Nginx + 网关层 |
| 密码存储 | bcrypt 加盐哈希 | Java UserService |
| 隐私脱敏 | 市民姓名隐藏中间字、手机号中间 4 位脱敏 | 展示/查询/导出全链路 |
| 明文查看审计 | 仅管理员可申请查看明文隐私，操作单独审计留痕 | Java AuditService |
| Token 管理 | JWT Access Token + Redis 黑名单 | Spring Security |
| 暴力破解防护 | 连续 5 次失败锁定 10 分钟 | Redis + UserService |
| AI 内容标识 | AI 生成内容显式标识"AI生成·置信度X%"并记录决策依据 | ai_generation_log |
| 日志不可篡改 | 审计日志仅查询，不支持删除/修改，永久留存 | Java LogService |

### 2.6 接口前缀约定

| 调用方 | 前缀 | 说明 |
|--------|------|------|
| 市民端 | `/api/v1/public/` | 市民；登录/短信验证码/注册等部分接口免 Token |
| 管理端 | `/api/v1/admin/` | 系统管理员 JWT Token + RBAC 权限 |
| 部门端 | `/api/v1/staff/` | 部门/街道办人员 JWT Token，按归属自动过滤数据范围 |
| Java→Python AI | `/ai/v1/` | 内网调用，IP 白名单 + 内网签名 |
| 通用服务 | `/api/v1/common/` | 文件上传等跨角色通用能力，所有登录角色可用 |

## 三、公众端接口 — 认证模块

> **模块说明**: 公众认证是本系统入口。市民采用"手机号 + 短信验证码"轻量化登录，无需注册即可上报诉求；内部工作人员（街道办/城管/物业/民生部门）通过自助注册申请开设账号，经管理员审核通过后以"工号 + 密码"登录政务后台。多用户类型通过差异化登录入口与 JWT 角色隔离，公众端与政务后台完全隔离。

### 3.1 工作人员自助注册

> **功能**: 面向街道办、城管、物业、民生部门工作人员。填写姓名、工号、所属单位、归属类型、辖区/部门、手机号、验证码、密码等，提交后进入"待审核"状态，经管理员审核通过后方可登录。密码 bcrypt 加盐存储。

**接口路径**: `POST /api/v1/public/staff-register`

**请求参数**:

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| name | String | 是 | 姓名 |
| job_no | String | 是 | 工号（6-20 位字母数字组合，唯一） |
| company | String | 是 | 所属单位 |
| user_type | String | 是 | 归属类型：`STREET`/`URBAN`/`PROPERTY`/`LIVELIHOOD` |
| region | String | 是 | 对应辖区/部门 |
| phone | String | 是 | 11 位手机号 |
| sms_code | String | 是 | 短信验证码 |
| password | String | 是 | 登录密码（≥8 位，含数字+字母+特殊字符） |
| confirm_password | String | 是 | 确认密码 |

**请求示例**:

```json
{
  "name": "张三",
  "job_no": "GWH2026001",
  "company": "XX街道办事处",
  "user_type": "STREET",
  "region": "XX区XX街道",
  "phone": "13812345678",
  "sms_code": "123456",
  "password": "Abc@12345",
  "confirm_password": "Abc@12345"
}
```

**响应参数**:

| 参数 | 类型 | 说明 |
|------|------|------|
| user_id | Long | 新注册用户 ID |
| audit_status | String | 审核状态（固定返回 `PENDING`） |

**成功响应示例**:

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "user_id": 2001,
    "audit_status": "PENDING"
  },
  "timestamp": 1785100800
}
```

**技术说明**:

| 项目 | 方案 |
|------|------|
| 工号唯一性 | 提交前实时校验，已存在则提示"该工号已注册" |
| 密码存储 | bcrypt 加盐哈希，明文不落库 |
| 审核状态 | 默认置 `false`（待审核），不可登录 |
| 结果反馈 | 成功后提示"注册申请已提交，请等待管理员审核" |

### 3.2 发送短信验证码

> **功能**: 市民输入 11 位手机号获取 6 位数字短信验证码，用于登录或注册。校验手机号合法性，防止恶意刷取。

**接口路径**: `POST /api/v1/public/sms/code`

**请求参数**:

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| phone | String | 是 | 11 位手机号 |
| scene | String | 是 | 场景：`LOGIN`/`REGISTER` |

**请求示例**:

```json
{
  "phone": "13812345678",
  "scene": "LOGIN"
}
```

**响应参数**:

| 参数 | 类型 | 说明 |
|------|------|------|
| expire_seconds | Integer | 验证码有效时长（秒） |
| retry_after | Integer | 下次可重发间隔（秒） |

**成功响应示例**:

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "expire_seconds": 300,
    "retry_after": 60
  },
  "timestamp": 1785100800
}
```

**技术说明**:

| 项目 | 方案 |
|------|------|
| 验证码 | 6 位数字，有效时长 5 分钟，Redis 缓存 |
| 防刷 | 限制同手机号 60 秒内重发、同 IP 限频 |

### 3.3 市民验证码登录

> **功能**: 市民使用手机号 + 短信验证码登录，返回短期 JWT Token，跳转公众端诉求首页。

**接口路径**: `POST /api/v1/public/login`

**请求参数**:

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| phone | String | 是 | 11 位手机号 |
| sms_code | String | 是 | 短信验证码 |

**请求示例**:

```json
{
  "phone": "13812345678",
  "sms_code": "123456"
}
```

**响应参数**:

| 参数 | 类型 | 说明 |
|------|------|------|
| access_token | String | JWT Token |
| expires_in | Integer | 过期时间（秒） |
| user_type | String | 固定 `CITIZEN` |
| masked_phone | String | 脱敏手机号 |

**成功响应示例**:

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "access_token": "eyJhbGciOiJIUzI1NiIs...",
    "expires_in": 7200,
    "user_type": "CITIZEN",
    "masked_phone": "138****5678"
  },
  "timestamp": 1785100800
}
```

**技术说明**:

| 项目 | 方案 |
|------|------|
| Token 生成 | JWT，携带 userType=CITIZEN，仅公众端权限 |
| 权限隔离 | 市民 Token 无法访问 /api/v1/admin/、/api/v1/staff/ |
| 验证码核验 | 一次性，校验通过即失效 |

## 四、公众端接口 — 诉求与消息通知模块

> **模块说明**: 市民诉求上报核心流程。市民在 AI 辅助下填写诉求（实时推荐标题、补全描述、提示缺失要素），上传图片/视频佐证；系统自动检测诉求类别，多类诉求自动拆分为多个独立诉求。表单采用"分级行政区划选择 + 详细地址补充 + 宽泛诉求开关"，地点信息与诉求文本分离采集，支撑"检测拆分 → 清洗匹配 → 分类建单"的解耦处理。

### 4.1 提交诉求

> **功能**: 市民提交诉求（诉求文本 + 分级区划 + 详细地址 + 宽泛诉求开关 + 附件）。提交后生成唯一诉求编号，初始状态"待AI检测"，AI 检测与拆分完成后进入"自动处理中"。

**接口路径**: `POST /api/v1/public/appeal`

**请求参数**:

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| title | String | 是 | 诉求标题 |
| content | String | 是 | 详细诉求内容 |
| province | String | 是 | 省级行政区划 |
| city | String | 是 | 市级行政区划 |
| district | String | 是 | 区级行政区划 |
| street | String | 是 | 街道（乡镇） |
| community | String | 否 | 社区 |
| address_detail | String | 否 | 详细地址补充（点位/楼栋/路段等） |
| broad_flag | Boolean | 否 | 宽泛诉求开关，默认 false |
| attachment_ids | Array | 否 | 已上传附件 ID 列表 |

**请求示例**:

```json
{
  "title": "XX路段占道经营严重",
  "content": "XX区XX街道XX路段每天傍晚有大量摊贩占道经营，影响通行和环境卫生……",
  "province": "XX省",
  "city": "XX市",
  "district": "XX区",
  "street": "XX街道",
  "community": "XX社区",
  "address_detail": "XX路与XX路交叉口",
  "broad_flag": false,
  "attachment_ids": [31001, 31002]
}
```

**响应参数**:

| 参数 | 类型 | 说明 |
|------|------|------|
| appeal_no | String | 诉求编号 |
| status | String | 初始状态 `PENDING_AI`（待AI检测） |
| detected_categories | Array | 检测到的类别（异步返回，可能为空） |

**成功响应示例**:

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "appeal_no": "AP20260821123456",
    "status": "PENDING_AI",
    "detected_categories": []
  },
  "timestamp": 1785100800
}
```

**技术说明**:

| 项目 | 方案 |
|------|------|
| 编号生成 | 诉求编号全局唯一，规则 `AP + 时间戳 + 序号` |

### 12.1 通用文件上传

> **功能**: 通用文件上传，支持处置凭证、现场照片、诉求附件等所有业务场景的文件上传。返回文件存储信息后，由业务接口通过 file_url 关联到对应工单或记录。

**鉴权要求**: 所有已登录角色均可调用（市民/街道办/部门/Admin），Token 通过 Header 传递

**Content-Type**: `multipart/form-data`

| 参数名 | 类型 | 必填 | 说明 |
|------|------|------|------|
| file | File | 是 | 上传文件，单个 ≤10MB |
| biz_type | String | 是 | 业务类型枚举：appeal_attachment（诉求附件）/ dispose_proof（处置凭证）/ dispose_photo（现场照片）/ avatar（头像）/ archive_export（归档导出临时文件） |

```
POST /api/v1/common/upload
Content-Type: multipart/form-data

file=@现场照片_20260821.jpg
biz_type=dispose_photo
order_id=31001
```

**响应参数**:

| 参数 | 类型 | 说明 |
|------|------|------|
| file_id | Long | 文件 ID |
| file_name | String | 原始文件名 |
| file_url | String | 文件访问地址（相对路径） |
| file_size | Long | 文件大小（字节） |
| file_type | String | MIME 类型 |
| upload_time | String | 上传时间（ISO 8601 + 东八区） |

**成功响应示例**:

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "file_id": 10086,
    "file_name": "现场照片_20260821.jpg",
    "file_url": "/uploads/dispose_photo/2026/08/21/abc123.jpg",
    "file_size": 2048576,
    "file_type": "image/jpeg",
    "upload_time": "2026-08-21T18:30:00+08:00"
  },
  "timestamp": 1755772200
}
```

**错误码**:

| code | 说明 |
|------|------|
| 400 | 文件为空 / 文件大小超限 / biz_type 非法 / order_id 缺失 |
| 401 | Token 无效或过期 |
| 413 | 文件体积超过服务端上限 |
| 500 | 存储服务异常 |

**使用流程说明**:

1. 前端先调用本接口上传文件，获取 `file_url`
2. 再调用业务接口（如 `PUT /api/v1/staff/orders/{id}/dispose`）时，将 `file_url` 作为附件参数传入
3. 业务接口仅保存文件引用，不处理实际文件流
